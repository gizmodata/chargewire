---
title: Graceful shutdown
description: "How a Chargewire server drains: health reports not_serving, new sessions and statements get 503 server_draining with Retry-After, and running statements may finish."
---

import Diagram from '../../../components/Diagram.astro';
import Spec from '../../../components/Spec.astro';

A server that is shutting down stops accepting new sessions and statements (`503
server_draining`, with `Retry-After`), reports `not_serving` on health so load balancers take it
out of rotation, lets running statements finish within its grace period, and then cancels what
remains with `cancel_reason: server_shutdown` (<Spec s="11.1" />).

<Diagram name="graceful-shutdown" alt="An operator sends SIGTERM while a long query runs; health answers 503 draining, a new statement answers 503 server_draining with Retry-After, and the running statement still succeeds and its result can be read." />

These commands run against a server of their own with a 30-second grace period; `SERVER_PID` is
its process id.

```bash test profile=drain
CHARGEWIRE=http://127.0.0.1:31337
TOKEN=$(curl -s $CHARGEWIRE/chargewire/v1/auth/token -H 'Content-Type: application/json' \
  -d '{"grant_type": "password", "username": "joe", "password": "s3:cret"}' | jq -r .access_token)
AUTH="Authorization: Bearer $TOKEN"
SESSION=$(curl -s $CHARGEWIRE/chargewire/v1/sessions -H "$AUTH" -H 'Content-Type: application/json' -d '{}' | jq -r .session_id)
curl -s $CHARGEWIRE/chargewire/v1/health
```

```json output
{"status":"serving"}
```

A long query is running when the operator stops the server:

```bash test profile=drain
STATEMENT=$(curl -s $CHARGEWIRE/chargewire/v1/sessions/$SESSION/statements -H "$AUTH" -H 'Content-Type: application/json' \
  -H 'Prefer: respond-async' -d '{"sql": "SELECT sum(i) AS total FROM range(6000000000) t(i)"}' | jq -r .statement_id)
kill -TERM "$SERVER_PID"
sleep 0.5
curl -s -i $CHARGEWIRE/chargewire/v1/health | tr -d '\r' | grep -E '^(HTTP|\{)'
```

```text output
HTTP/1.1 503 Service Unavailable
{"status":"not_serving","reason":"draining"}
```

New work is refused, with how long to wait before trying again (an integer number of seconds,
<Spec s="2.6" />):

```bash test profile=drain
curl -s -i $CHARGEWIRE/chargewire/v1/sessions/$SESSION/statements -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"sql": "SELECT 1"}' | tr -d '\r' | grep -E '^(HTTP|Retry-After|\{)' | sed 's/,"request_id".*/,…}/'
```

```text output
HTTP/1.1 503 Service Unavailable
Retry-After: …
{"type":"urn:chargewire:error:server_draining","title":"Server shutting down","status":503,"code":"server_draining","detail":"the server is shutting down",…}
```

The statement that was running finishes, and its result can still be read:

```bash test profile=drain
curl -s $CHARGEWIRE/chargewire/v1/sessions/$SESSION/statements/$STATEMENT -H "$AUTH" -H 'Prefer: wait=30' | jq -r .state
curl -s $CHARGEWIRE/chargewire/v1/sessions/$SESSION/statements/$STATEMENT/result -H "$AUTH" -o total.arrows
python3 -c "import pyarrow.ipc as ipc; print(ipc.open_stream('total.arrows').read_all().to_pylist())"
```

```text output
succeeded
[{'total': Decimal('17999999997000000000')}]
```

Once nothing is left to run, or the grace period ends, the server stops. A client that gets
`server_draining` retries after `Retry-After`, on another instance if there is one; health's
`starting` and `check_failed` reasons are also `503 not_serving`.
